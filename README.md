# primedos

Терминальная программа генерации нагрузки на веб-цель: TUI на bubbletea, движок на горутинах, телеметрия по счётчикам с точным монотонным временем, независимый пробник живости цели.

## Сборка

```bash
make build           # → ./primedos, статический бинарь
make run             # go run ./cmd/primedos
```

Требуется Go 1.22+. Зависимости: `charmbracelet/bubbletea`, `charmbracelet/lipgloss`, `golang.org/x/net/http2`, `golang.org/x/sys`, `gopkg.in/yaml.v3`.

## Запуск

```bash
./primedos                       # интерактивный режим
./primedos --dry-run             # интерфейс и телеметрия без трафика
./primedos --config config.yaml  # конфиг, флаги перекрывают файл
./primedos --target example.com --level 2 --mode 3 --duration 5m --workers 512 --rate 200
```

## Экраны

1. Стартовая строка `запускается ддос программа созданная тг @PrimeNikee`.
2. Баннер PRIMEDOS с анимацией искр (упрощённый при ширине < 80).
3. Уровень: 1 — лёгкий, 2 — средний, 3 — сложный (кумулятивно).
4. Цель: домен или URL, DNS-резолв, определение CDN/WAF.
5. Режим: до падения, бесконечный, фиксированное время.
6. Боевой экран: прогресс/ETA, скорость (bit/s, pps, rps), статус цели, uptime, объём, ошибки, лог.
7. Отчёт с сохранением JSON и CSV.

## Уровни и векторы

| Уровень | Векторы |
|---|---|
| 1 | `get-flood`, `post-flood`, `slowloris` |
| 2 | + `tls-flood`, `http2-reset` (CVE-2023-44487), `continuation-flood` (CVE-2024-27316), `rudy`, `slow-read`, `range-flood`, `api-flood` |
| 3 | + `syn-flood` (raw, нужен CAP_NET_RAW), `udp-flood`, `ws-flood`; включаются `multi-vector` и `adaptive` |

`adaptive` на старте измеряет задержку десяти типовых путей и переносит основную массу на три самых «дорогих» для сервера.

## Телеметрия

- Монотонные часы `CLOCK_MONOTONIC_RAW`, агрегация счётчиков каждые 100 мс, EWMA α=0.2.
- Раздельный учёт полезной нагрузки и байт «на проводе» (Ethernet + IP + TCP + IFG + TLS record).
- BPS, PPS и RPS считаются независимо: это разные узкие места.
- RTT p50/p95/p99 по кольцевому буферу 2048 замеров; потери и ретрансмиссии — из `TCP_INFO` (`Total_retrans`, `Segs_out`).
- Проверка offload (`ethtool -k`): при включённых TSO/GRO/LRO пишется предупреждение о завышенных размерах пакетов.
- Проверка аппаратных меток времени через `SIOCGHWTSTAMP`; без поддержки используется программное время.
- Раз в 60 с — сверка локальных счётчиков воркеров с глобальными, расхождение > 0.5% попадает в лог.

## Классификация цели

Три параллельные пробы каждые 500 мс: `HEAD /`, `GET <path>`, TCP-connect.

- `ONLINE` — любой ответ 2xx/3xx.
- `DEGRADED` — часть проб не прошла, либо задержка выросла более чем втрое от baseline.
- `OFFLINE` — обе HTTP-пробы упали (таймаут, reset, refused, 429/5xx), подтверждено двумя циклами подряд.

Код `400` относится к `DEGRADED`, а не к `OFFLINE`: на корректный запрос он чаще означает битый запрос, чем перегрузку.

## Флаги

| Флаг | Значение |
|---|---|
| `--config` | путь к yaml |
| `--target` | домен или URL |
| `--level` | 1..3 |
| `--mode` | 1 — до падения, 2 — бесконечно, 3 — фиксированное время |
| `--duration` | `30s`, `5m`, `1h` |
| `--workers` | общее число воркеров |
| `--rate` | лимит Мбит/с, `0` — без ограничения |
| `--proxies` | файл прокси, по одному в строке (`http://`, `socks5://`, `user:pass@host:port`) |
| `--dry-run` | без внешних соединений, кроме DNS |
| `--hw-ts` / `--no-ts` | аппаратные метки времени |
| `--socket` | unix-сокет для управления (JSON) |
| `--headless` | без TUI, движок под управлением сокета (только с `--dry-run`) |

## Отчёт

`report_<host>_<timestamp>.json` и `.csv`: цель, IP, CDN, уровень, режим, длительность, время до падения, объём на проводе и полезный, запросы, средняя/пиковая скорость, PPS/RPS, RTT p50/p95/p99, потери, ошибки, число живых прокси, финальное состояние.

## Бот в Telegram

Бот управляет только сессиями `--dry-run`: показывает телеметрию, запускает и останавливает прогон интерфейса без трафика. Боевые сессии из Telegram не запускаются, сервер отвечает `403` на такой запрос.

```bash
cp bot.yaml.example bot.yaml
$EDITOR bot.yaml                      # token от BotFather и allowed_users
make build
./primedos --dry-run --headless --socket "$XDG_RUNTIME_DIR/primedos.sock"
./primedos-bot --config bot.yaml      # во втором терминале
```

Команды: `/start` (уровень, цель, режим), `/status`, `/stop`, `/reports`. Пока `allowed_users` пуст, бот отвечает только твоим `id`, чтобы его можно было вписать в конфиг.

## Ограничения

- `syn-flood` требует `CAP_NET_RAW` (root); без него вектор пропускается с записью в лог.
- Прокси используются только HTTP-векторами; raw-векторы идут напрямую.
- Аппаратные метки времени влияют на точность замеров задержки, но скорость считается по счётчикам и от них не зависит.
